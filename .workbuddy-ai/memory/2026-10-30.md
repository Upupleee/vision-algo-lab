## 搭建 .venv 虚拟环境（vision-algo-lab）

**背景**：用户跑 `traditional/template_matching/ncc_matching.py` 报
`ModuleNotFoundError: No module named 'scipy'`，随后 `pip install scipy` 报
「无法将 pip 项识别为 cmdlet」而求助。

**根因（两条，都不是「缺 scipy」这么简单）**：

1. `pip` 不在 PATH。本机唯一可用解释器是 WorkBuddy 自带的
   `C:\Users\Administrator\.workbuddy-ai\binaries\python\versions\3.13.12\python.exe`
   （实为 3.13.14），其 `Scripts\` 未进 PATH；系统里无独立 Python、无 conda。
   正确姿势是 `python -m pip`。
2. 清华源 `pypi.tuna.tsinghua.edu.cn` 对 **pip 26.1.2 的 UA 返回 403**，
   pip 表现为 `ERROR: Could not find a version ... (from versions: none)`，
   极易误判成网络不通。curl 同一 URL 是 200，`pip index versions` 换
   pypi.org / 阿里云 / 腾讯云源全部正常。→ **改用阿里云源**。

**已做的事**：

- 在项目根建 `.venv`（387MB），装完 `requirements.txt`：
  numpy 2.5.4 / opencv-python 5.0.0.93 / scipy 1.18.1 / matplotlib 3.11.2。
- 写 `.venv/pip.ini` 固化阿里云源（venv 级配置，重建 venv 会丢，README 已注明）。
- 更新 `README.md`「快速开始」：环境准备 / 镜像源坑 / `-m` 运行方式 / dl 线单独建环境。
- `.gitignore` 补 `.venv-dl/`。

**验证结果（实测）**：

- `python -m tests.test_smoke` → 8/8 通过
- `python -m unittest tests.test_pose_ncc` → 37 tests OK（5.6s）
- `python -m traditional.template_matching.ncc_matching` → 得分 0.9618，误差 0.2013px

**关键坑（以后别再踩）**：

- **必须用 `-m` 模块方式运行，不能用脚本路径直跑。** 各模块 `__main__` 里是
  `from data.synthetic import ...` 包内绝对导入，直跑时 `sys.path[0]` 是脚本
  所在目录而非项目根 → `ModuleNotFoundError: No module named 'data'`。
- **dl 线必须单独环境**：`torch>=2.2` 要 `numpy<2`，传统线是 numpy 2.5.x，不可共存。
- venv 的 base 指向 WorkBuddy 目录，WorkBuddy 升级换版本号后 venv 会失效，需重建。

**`sys.path[0]` 的实测差异**（这是反复踩坑的根因，务必记住）：

| 运行方式 | `sys.path[0]` |
|---|---|
| `python traditional/xxx/ncc_matching.py` | `...\traditional\template_matching`（脚本目录）|
| `python -m traditional.template_matching.ncc_matching` | 项目根（= cwd）|

### 顺带发现的真 bug（未修，待卡布达定夺）

`data/synthetic.py: make_template_scene()` 的 `mask` 用错了：

```python
mask = cv2.warpAffine(np.ones(img_size, np.float32), M, dsize, ...)  # 全图 mask
img = np.where(mask > 0, warped, bg)
```

全图 mask 平移后覆盖所有有效区域 → `bg` 只在平移出界的窄条生效，
**图像大部分是黑色 canvas（0）而非背景纹理**。实测：均值 30.28，
右下角 20×20 均值 -0.22，接近 0 的像素占 16.4%。

正确写法应是给**模板**做 mask：

```python
m = np.zeros(img_size, np.float32); m[:h, :w] = 1.0
mask = cv2.warpAffine(m, M, dsize, flags=cv2.INTER_NEAREST)
```

后果：当前测试背景过于干净，NCC 得分虚高、匹配难度偏低。
**改它会动测试基线数值**，所以没擅自动手。

## 接真实数据集 RTImg（对焦线）

### 数据集实况（实测，2026-10-30）

- 路径 `RTImg/`，1.3 GB，**12 个场景共 110 帧**，6016×4016 BGR uint8，10~13 MB/张
- 命名 `<NNN>-<DDDD>-<ZZZZ>.<ext>`：目标编号 / 目标实际距离 mm / 拍摄对焦距离 mm
- 组 1-6、8-11 的真值帧**精确命中**（ZZZZ == DDDD）；组 7 的 1040 无对应帧，退到 1004
- 组 111 是异类：4 帧、358×293、png/jpg 混用
- **`RTImg/README` 说的 `-0000` 自动对焦参考帧在这批数据里不存在**
- 真值改用「对焦距离最接近目标距离的帧」`argmin |ZZZZ−DDDD|`，实测与评分峰值吻合
- `001/INFO` 有 `DTS 125cm / Camera Recorded FD 126cm / Focus Point Nose Dimple`

### 修复：`focus_measures._prep()` 顺序错误（真 bug）

原来先 `astype(np.float64)` 再 `cvtColor` → **彩色图一进 tenengrad 就崩**
（`cvtColor` 不认 CV_64F，只接受 8U/16U/32F）。已改为先降灰度再转 float64。
修复后 5 种 dtype/通道组合全通，7 个函数对 uint8 BGR 全 OK。

### 新增文件

- `traditional/autofocus/source.py`：`Frame` / `parse_frame` / `FolderSource` /

### 关键性能数据（6016×4016 实测）

| 项 | 耗时 |
|---|---|
| JPEG 解码 | **~190 ms/帧（硬成本）** |
| tenengrad 全图 | ~335 ms |
| tenengrad 中心 70% ROI | ~24 ms |
| 110 帧 × 7 函数（ROI） | 175 s |

**降采样路线已证伪**：`IMREAD_REDUCED_*` 解码只从 190→110 ms，但灵敏度崩塌
（007 组 1000mm 帧归一化评分从 0.05 塌到 0.52，与 1004mm 几乎分不开）。
评价函数测的就是模糊，不能先低通再测。**优化只能靠 ROI。**
