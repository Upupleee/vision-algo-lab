本域有两条任务分支，每个分支都对照**历史演进线＋工程实践线**。OCR 从字符图像推断文字；条码从受码制约束的图形恢复码字和数据。文本检测不是文字识别，码制规范不是检测网络，校验通过不是业务真实性证明，成功解码也不是质量等级合格。

核验日期：**2026-11-04**。年份指所列原论文或规范版本，不是思想唯一首创、软件版本或仓库实现日期。OCR 选取 6 个有原始资料的代表节点；编码另列码制、质量评定和业务语法节点，不能将两者拼成“传统 OCR → 二维码 → 大模型”的替代链。不提供截至核验日“最新最佳”排名，也没有跨方法统一实测。

来源编号在本文内独立。文末逐 URL 标明**全文入口及实际读取范围／摘要／书目／受限**；取得 PDF 的一段正文不等于逐页读完全文，读取官方标准产品页不等于获得标准正文。单篇原文支持的机制默认 `[SINGLE-SOURCE]`；同一论文的作者页、预印本和期刊记录只能交叉核对版本，不能算三份独立性能证据。资料不足时保留缺口，不从编号、标题或搜索片段补造标准条款。

## 2. 核心维度与分支总图

| 核心维度 | OCR 要解决的问题 | 编码要解决的问题 | 需要留存的工程证据 |
|---|---|---|---|
| 成像与定位 | 字高、笔画宽、方向、弯曲、多行和背景 | 最小模块、条空边界、静区、定位结构、透视和 DPM 反光 | 原图、曝光、运动状态、ROI 与坐标映射；不能只保存增强图 |
| 表示与切分 | 固定字符块、特征序列、图像 patch；切字错误是否传播 | 一维宽度序列或二维采样网格；码制识别是否可靠 | 字符框／文本框或网格、采样点、失效区域 |
| 识别与解码约束 | 字符集、CTC 对齐、生成词元、语言和格式先验 | 合法码字、控制状态、校验／纠错、数据编码 | 原始候选、未修饰识别串、码字和规范版本 |
| 拒识与风险 | 未知字、低分差、合法但错误的序列号 | 不支持码制、结构失败、校验失败、读错但碰巧合法 | 拒绝原因、误读与不可读分别计数；不强制返回字符串 |
| 质量与追溯 | CER、整串正确率、检测漏检及业务误放行 | 解码率、误解码率、独立的标准质量评定 | 真值来源、分母、复检、设备／解码器／应用规则版本 |
| 资源与泛化 | 标注成本、字库维护、模型和长序列延迟、跨字体域移 | 多码制覆盖、纠错预算、验证仪及标定成本 | 按设备／批次／产品隔离验证；端到端尾延迟 |

OCR 识别分支可写为“切字模板教学基线 ↔ 字符 CNN → 序列识别（CRNN＋CTC）／预训练生成式识别（TrOCR）”；文本检测（EAST／DB）作为并行前端向识别器提供 ROI。CTC 是对齐与训练目标组件，不是独立的图像检测器。编码分支则是“定位与采样 → 按指定码制解码 → 校验／纠错 → 业务语法 → 追溯”，质量评定是一条旁路，不是识别网络置信度的别名。[cite:1](#source-1)[cite:2](#source-2)[cite:3](#source-3)[cite:4](#source-4)[cite:5](#source-5)[cite:6](#source-6)[cite:8](#source-8)[cite:12](#source-12)[cite:15](#source-15)

|---|---|---|---|---|---|

| O-H6：TrOCR，2021 预印本／AAAI 2023 | CNN／RNN 与另接语言模型的分离；改变表示和生成方式 | 预训练图像 Transformer＋文本 Transformer，生成 wordpiece 序列并微调 | 预训练／微调数据、词元协议、模型内存和生成延迟 | 文本识别模型不自动完成整页布局；语义先验可能偏向常见串，随机编号必须单独验证，不得用流畅性验收 | [cite:6](#source-6)[cite:7](#source-7) |

### 3.1 版本不能混写

- LeCun 等的代表期刊文献是 *Proceedings of the IEEE* 86(11), 2278–2324，1998；作者书目页的 2006 修改时间不是论文年份。它并非宣称 CNN 在 1998 才出现。[cite:1](#source-1)
- CTC 原文是 ICML 2006；本次读取训练目标和解码章节，未逐页验证全部实验或重现。`best path` 解码是近似，不保证得到总路径概率最大的字符串。[cite:2](#source-2)
- CRNN 的 arXiv v1 为 **2015-07-21**；期刊记录为 TPAMI 39(11), 2298–2304，**2017-11**。DOI 中出现 2016 不能独自证明具体首次在线日期；本文未补填该日期。[cite:3](#source-3)
- DB 的 arXiv v1 为 **2019-11-20**，v2 为 **2019-12-03**；AAAI 2020 页面标注 Published **2020-04-03**。这是论文网页出版字段，不混作会议实际举办日；DB++／后续扩展不并入此节点。[cite:5](#source-5)
- TrOCR 的 arXiv v1 为 **2021-09-21**，所查记录列 v5 **2022-09-06**；作者机构列 AAAI **2023-02**。这些是不同版本事件，不用模型名中的年份或仓库更新时间代替。[cite:6](#source-6)[cite:7](#source-7)

### 3.2 CTC 与生成式解码的工程差别

用现代记号概括 CTC：\(p(y\mid x)=\sum_{\pi\in B^{-1}(y)}\prod_t p(\pi_t\mid x)\)。折叠顺序是先合并相邻重复，再删除 blank：`A,A,blank,A → AA`。对目标长度 U、相邻相同目标字符对数 R，至少需要 T≥U＋R 个时间步；这是折叠规则的必要长度条件，不是识别成功保证。过度压缩图宽可能令训练对齐不可能；“模型损失能计算”也不表示原字形已被保留。[cite:2](#source-2)[cite:3](#source-3)

TrOCR 则按已生成词元和图像特征条件化后续生成。两条路线都需要训练和拒识，但错误诊断不同：CTC 先查输出步数、重复字符和 blank；生成式识别先查裁切、词元化、终止符、最大长度和先验干扰。不得把 CTC 分数或逐词元概率直接当作已校准的整串正确概率。自动格式修正必须另存修改前后结果，不能覆盖原始识别证据。[cite:2](#source-2)[cite:6](#source-6)

## 4. 历史演进线 B：编码、质量标准与业务语法

这里记录的是**所选规范节点**，不推断 Code 128／QR／Data Matrix 的发明年份。标准产品页能证明版本与摘要范围，却通常不能证明相邻版的逐条技术改进。下表“改进”表示这一规范层解决的工程问题；没有正文证据的版间差异明确未核验。

| 节点／版本 | 类别与前序瓶颈 | 该规范层提供的机制／工程改进 | 代价与遗留问题 | 证据 |
|---|---|---|---|---|
| B-H1：ISO/IEC 15417:2007，第 2 版，2007-06 | Code 128 码制；不同实现需要统一编码与解码契约 | 官方摘要覆盖字符编码、尺寸、解码算法和应用参数；不是学习字符外观 | 需完整码表、状态解析和合规测试；B01 固定 B 集只作教学，不满足完整码制 | [cite:8](#source-8) |

| B-H3：ISO/IEC 18004:2024，第 4 版，2024-08 | QR 码制；需一致的格式、编码和参考解码 | 官方摘要覆盖符号格式、尺寸、纠错、参考解码、生产质量要求 | 不能借用 Data Matrix 参数；2015→2024 细节未核验，容损比例不作任意遮挡保证 | [cite:11](#source-11) |

| B-H7：15417:2007/Amd 1:2026，2026-01 | Code 128 维护节点；只锁基础版可能遗漏适用修订件 | 官方页面确认已发布并适用于 2007 基础版；提醒配置管理记录修订件 | **只核验存在及适用对象；未取得正文，不声称改变了校验、码表或解码性能** | [cite:9](#source-9) |

## 5. 工程实践线：选型与交接

以下均是**待评估方案**，不是仓库可调用能力或标准强制要求。

| 任务／约束 | 起始路线及输入输出 | 为什么先选它 | 升级触发与成本 | 卡片／边界 |
|---|---|---|---|---|
| 固定字体、短串、字间隔稳定 | 已定位单行 → 投影切字＋模板相关 → 字符串／拒识 | 容易逐字解释，字库与切分证据可检查 | 连字／变字体导致切分失效时评估序列识别；先改采集而不是盲增模板 | [O01](algorithm_cards/remaining_domains.md#o01-切字加模板相关-ocr)，未实现 |
| 可变长度、连笔或切字脆弱 | 文本 ROI → CRNN＋CTC → 原串、候选、拒识 | 减少显式字符边界依赖 | 长串、曲线、字符集变化需整形及训练数据；复杂模型不免除未知字测试 | [序列族边界](algorithm_cards/remaining_domains.md#o01-切字加模板相关-ocr)，无独立完成卡 |
| 全图小字、多方向文本 | 原图 → EAST 或 DB 候选 → 坐标回填／裁切 → 独立识别 | 检测和识别分开定位瓶颈 | 高分辨率、切片、曲线整形增加开销；切片漏边必须测试 | [ROI 交接 P36](algorithm_cards/preprocessing.md#p36)、[缩放 P37](algorithm_cards/preprocessing.md#p37) |
| 手写／印刷域可提供微调数据 | 文本 ROI → TrOCR → 词元与字符串 | 可评估预训练视觉和语言表示 | 随机编号、罕见词、生成长度和域偏移；同时保留较简单基线对照 | [学习组件](algorithm_cards/learning_components.md)，不是已接 OCR |
| 一维追溯码 | 成像／校正 → 明确 Code 128 支持集 → 码字／校验 → 业务层 | 用码制约束而非 OCR 猜条纹 | 完整 A/B/C、控制符和业务字段需额外接入；不支持内容明确拒绝 | [B01](algorithm_cards/remaining_domains.md#b01-code-128-b-读码与校验子集) 仅固定 B 集 |
| 二维标签与金属 DPM | 明确码制 → 网格采样／解码 → 业务验证；另作相应质量评定 | 把可读性、内容与质量分开 | DPM 先试照明几何与表面反射；增加算力不能补回饱和模块 | [编码族边界](algorithm_cards/remaining_domains.md#泛称各列的族级边界)，QR／Data Matrix 未实现 |

### 5.1 排障顺序与可观测证据

| 症状 | 首先检查的证据 | 排查／改动顺序 | 不应采取的捷径 |
|---|---|---|---|
| 整行漏检，小字突然不可读 | 原图字高、笔画、缩放前后 ROI、饱和和焦点 | 采集 → 真实缩放倍率 → 检测输入 → 候选阈值 | 只换更大识别器或将上采样当新增细节 |
| `11` 读成 `1`、长串掉字 | 切分框或 CTC T/U/R、blank 与重复折叠、输入宽度 | 先判切分／对齐失效，再查网络与解码 | 先删 blank 后合并重复；忽略最大长度截断 |
| O/0、I/1 误读且模型高分 | 原字形、候选差值、字符集、原串与修正串 | 采集可辨识性 → 字库／训练覆盖 → 拒识 → 业务复检 | 用字典把所有结果修成一个合法串并覆盖证据 |
| 文本框正确而字符串错位 | 框角点次序、裁切方向、整形图、ROI→原图映射 | 坐标／朝向 → 采样支持 → 识别输入规范 | 把定位 IoU 高当整串正确 |
| 条码能定位但解不开 | 模块剖面／网格、静区和停止结构是否完整、是否欠采样 | 光学／运动 → 几何采样 → 码制与支持集 → 解码参数 | OCR 读取人眼可读字符替代码体解码并报告“解码成功” |
| 多次读码载荷不一致 | 原码字、纠错／校验状态、扫描线结果、独立业务真值 | 冻结现场图 → 区分读错与不可读 → 复检／隔离 → 查采样 | 只取多数或第一条合法串直接放行 |
| 能解码但验证仪等级低 | 所用标准版次、设备标定、测量条件与原始报告 | 先确认评定适用范围，再排印刷／标记和照明 | 用神经网络置信度、清晰度评分或一次解码替代标准等级 |
| 同一码库返回不同业务字段 | 原始字节、字符编码、控制状态、应用规则版本 | 解码载荷 → 字符／控制信息 → 字段语法 → 外部业务核对 | 见到可打印文本便丢弃分隔／控制信息 |

### 5.2 验收设计与追溯输出

- **OCR 分层验收**：检测召回及匹配协议、字符编辑错误率 CER、整串完全正确率分别报告；字符替换／删除／插入不能混为分类准确率。CER 分母为参考字符数，空参考另列；字符插入可能令 CER 超过 1。整串正确率以全部应读样本为分母，另报拒识率，不能删除拒识后只给“高准确率”。[cite:2](#source-2)
- **编码分层验收**：在独立载荷真值下分别统计正确解码、误解码、不可读和不支持；质量等级另由声明版本的测量程序给出。校验或纠错成功并不能证明载荷就是该工件的业务编号。[cite:8](#source-8)[cite:12](#source-12)[cite:13](#source-13)
- **数据组织**：按相机、产线、印字设备、批次和字体分组隔离；同一标签连拍或裁块不能跨训练／测试。必须包含新编号、近似字符、粘连、断笔、污损、透视、静区不足和饱和，单列各失效类型。
- **延迟与风险**：测原图读取至业务输出的耗时分布，包括检测、整形、识别／解码、超时和复检；声明测量机器、模型、输入尺寸和批量。误放行代价由业务定义，不给通用阈值。
- **最小输出契约**：图像标识、时间戳、原图 ROI、几何映射、原始识别串／字节／码字、候选或校验状态、业务解析结果、拒绝原因、解码器／模型／标准版本。读到 URL 只当数据，不自动打开或执行。

这些是测试设计，**没有在本仓库执行 OCR／条码端到端测试或标准质量评测**；既有匹配／对焦测试不能继承为本域测试通过。
